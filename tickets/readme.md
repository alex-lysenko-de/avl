## Папка `tickets`

Папка `tickets` содержит тикеты, предназначенные для ИИ-агента, который может выполнять функции разработчика, архитектора, ревьюера и другие задачи.

Каждый тикет может содержать:

* статус;
* описание задачи;
* дополнительные файлы, относящиеся к тикету.

Пользователь может управлять тикетами с помощью голосовых команд, например:

* создать тикет;
* закрыть тикет;
* работать над тикетом;
* обновить документацию согласно тикету;
* выполнить другое действие, связанное с тикетом.

Правила работы с папкой `tickets` должны быть описаны в `CLAUDE.md`.

### Общие правила работы с тикетами

1. **Не начинай формировать требования, если задача неоднозначна.**
   Сначала проанализируй описание и определи, достаточно ли информации для реализации.

2. **Если информации недостаточно:**

   * задай уточняющие вопросы;
   * спрашивай только то, что влияет на реализацию;
   * не задавай вопросы ради вопросов;
   * если существует несколько вариантов реализации, перечисли их и попроси пользователя выбрать один.

3. **Не делай важных предположений самостоятельно.**
   Любое предположение, которое может повлиять на реализацию, должно быть вынесено на согласование с пользователем.

4. **Всегда разделяй информацию на четыре категории:**

   * подтвержденные требования;
   * предположения;
   * открытые вопросы;
   * рекомендации (если есть).

5. **Формат уточняющих вопросов должен быть удобен для голосового и клавиатурного ввода.**

   Каждый вопрос получает уникальный идентификатор, например `[Q1]`, `[Q2]`.

   Каждый вариант ответа также получает идентификатор, например `[v1]`, `[v2]`, `[y/n]`.

   Используй короткие ссылки на вопросы и варианты ответов, чтобы пользователь мог отвечать одной короткой фразой:

   > «Вопрос 1, вариант 2»
   > «Вопрос 3, да»
   > «Вопрос 4, текст: lorem ipsum...»

   Для ответа с клавиатуры формат должен требовать минимум нажатий:

   > `Q1v2 Q3y Q4:lorem ipsum...`

   Не требуй от пользователя повторять длинные идентификаторы или формулировки вопросов.

   Наиболее логичный или предпочтительный вариант ответа помечай как **«рекомендуется»**.
