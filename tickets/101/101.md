
Добавь к wiki описание Что такое папка C:/docs и для чего она нужна

Это файловое хранилище приложения — отдельное от кода программы (код лежит в C:\__docs_new, а данные в C:\docs). Путь задаётся в config.ini или config.yml

C:/docs/
├── base/          — общие («базовые») шаблоны, единые для всех клиентов
├── tenants/        — папка на каждого клиента (тенанта)
└── tmp/            — временные файлы

1. base/ — общий фонд шаблонов

base/
├── templates/      — шаблоны документов
│   └── 1-СМ-Система менеджменту/
│       ├── Настанова/
│       ├── Положення/
│       ├── Процедури/
│       └── Форми/
│           ├── ФСМ-4.1 Заява про неупередженість.docx   ← сам шаблон Word
│           └── ФСМ-4.1 Заява про неупередженість.cfg    ← его "паспорт": какие поля формы к нему прилагаются
└── html_forms/     — (опционально) кастомные HTML-формы для отдельных шаблонов

Каждый документ — это пара файлов с одинаковым именем: .docx (сам бланк Word с Jinja2-плейсхолдерами вида {{ company.name }}) и .cfg (описание, какие поля веб-формы нужно показать пользователю, чтобы их заполнить). Программа сама сканирует эти папки — чтобы добавить новый документ, достаточно положить пару файлов на диск, без изменения кода.

Папка разбита по разделам системы менеджменту (Настанова / Положення / Процедури / Форми) — это просто структура категорий, видимая пользователю как дерево шаблонов.

2. tenants/ — данные конкретных организаций-клиентов

На диске сейчас реально существуют:
- company_aaa
- OTK_VINOGRADIV
- tenant_default
- UkrAutoKontrol
- Zrazkova_Comp

Внутри каждого тенанта:

tenants/<имя_тенанта>/
├── templates/   — точная копия структуры base/templates, но здесь тенант может
│                  держать СВОИ версии .docx/.cfg (переопределяя базовые)
├── files/       — уже заполненные и сохранённые документы этого тенанта
│   └── .../Форми/ФСМ-4.1 Заява про неупередженість.docx  + .pdf
└── html_forms/  — кастомные HTML-формы, специфичные для тенанта

Логика приоритета: когда пользователь открывает документ, программа сначала ищет файл в папке тенанта, и только если там его нет — берёт из base. Как только админ редактирует "чужой" (базовый) шаблон через встроенный редактор, система автоматически копирует его в папку тенанта (copy-on-write) — с этого момента тенант получает собственную независимую версию файла и перестаёт получать обновления базового шаблона.

Папка files/ — это результат работы: туда после заполнения формы сохраняются готовые .docx и сконвертированные .pdf. Есть два режима:
- «Единый документ» — файл просто перезаписывается при каждом сохранении (ФСМ-4.1....docx);
- «Архив» — сохраняются пронумерованные версии (000001.docx, 000002.docx…) в отдельной подпапке с именем документа (я нашёл такую пустую заготовку у Zrazkova_Comp — архивный режим для неё пока не использовался).

Итог одной фразой

base/ — это библиотека шаблонов документов, общая для всех; tenants/*/ — рабочее пространство каждой конкретной компании-клиента, где хранятся её персональные версии шаблонов (если она их правила) и все документы, которые она реально заполнила и сохранила.
