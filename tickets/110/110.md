GitHub Actions: тесты, сборка и публикация GitHub Release.

Контекст: см. `wiki/update_workflow.md` (§37-40) — GitHub Releases является источником дистрибутива, репозиторий публичный (подтверждено: https://github.com/alex-lysenko-de/avl уже public).

Что сделать:
* `.github/workflows/release.yml` — триггер на push в `main`: checkout → установка Python 3.11 → установка зависимостей → `pytest` → сборка exe (тикет 106) → сборка релизного пакета (тикет 108: ZIP + version.txt + manifest.json) → создание GitHub Release с тегом по версии из `pyproject.toml` → загрузка `avl_docs-v<version>.zip` и `manifest.json` как assets;
* если `pytest` или сборка падают — Release не создаётся (документ §38-39, "tests failed → no release");
* Release публикуется как обычный стабильный релиз (не pre-release), чтобы клиентский `update.ps1` мог полагаться на `latest release` (документ §5, §40).

Зависит от тикетов 106 и 108.
