Сборка релизного пакета (ZIP + version.txt + manifest.json).

Контекст: см. `wiki/update_workflow.md` — актуальное описание механизма обновления. GitHub Releases является источником дистрибутива; installer и отдельный Updater.exe на этапе разработки не используются.

Что сделать:
* `pyproject.toml` в корне проекта — единственный источник номера версии (`[project].version`), остальные файлы генерируются из него, вручную не редактируются;
* `scripts/create_manifest.py` — читает версию из `pyproject.toml`, вычисляет SHA-256 собранного ZIP, создаёт `manifest.json` вида `{"version": "...", "package": "avl_docs-v<version>.zip", "sha256": "..."}`;
* `scripts/build_release.bat` — после сборки exe (тикет 106) формирует `version.txt` (просто номер версии), кладёт его рядом с приложением, упаковывает `app/` + `version.txt` (+ `migrations/`, когда появятся) в `avl_docs-v<version>.zip`, вызывает `create_manifest.py`;
* результат: `avl_docs-v<version>.zip` + `manifest.json` — то, что будет прикладываться к GitHub Release (тикет 110).

Пользовательские данные (`data/`, `database.sqlite`, `backups/`, секреты) в пакет не входят.

Зависит от тикета 106.
